# TCode Bug 映射

默认 profile 面向表 `TCode bug管理`，但不保存或绑定任何飞书链接。每次运行都由用户提供目标 Base/Wiki URL。

## 规则优先级

用户本次命令优先。以下内容均为默认映射；用户可以覆盖任一字段，也可以要求任一字段留空。缺失值和冲突值作为预览提示，字段保持为空。

## Issue 元数据

- 状态：`opened → 未解决`，`closed → 已关闭`。
- 优先级：默认读取唯一的 `P0`、`P1`、`P2` 标签。
- 严重程度：优先读取 Issue 中的 `致命`、`严重`、`一般`、`轻微`、`建议优化` 标签；没有时使用：
  - `P0 → 致命`
  - `P1 → 严重`
  - `P2 → 一般`
- 同名严重程度标签与优先级映射不一致时保持为空并提示。
- 提交人：默认使用当前 `lark-cli` 飞书用户。飞书人员字段 API 需要 `openId`，单元格展示对应 `userName`。

## 模块

同时扫描标题的全部 `[...]` 前缀和所有 Issue 标签；前缀中的 `/`、`,`、`+`、`&`、`、` 会拆成多个信号。

| Issue 信号 | 飞书选项 |
| --- | --- |
| `Platform`、`Backend`、`平台后端` | `Tcode平台后端` |
| `Frontend`、`前端` | `Tcode前端` |
| `SCA` | `TcodeSCA` |
| `Audit` | `TcodeAudit` |
| `Verify` | `TcodeVerify` |
| `Fix`、`Vulnfix` | `TcodeFix` |

去重后按 profile 选项顺序整理候选。唯一候选直接写入；多个候选保持字段为空，并在预览中列出候选供用户选择。没有可识别信号时字段保持为空。

## 表结构

- `bug模块`：单选。
- `状态`、`优先级`、`严重程度`：单选。
- `提交人`：单用户字段。
- 其他字段、选项和写入模式以 `tcode-bug-profile.json` 为准。

实时校验只覆盖本次实际准备写入的字段。单选候选必须被实时选项接受；实时表中的空白和额外选项不影响合法候选。未填写字段不参与 Schema 门禁。
